## The idea

Three questions, in order. **The first is the one people skip, and it is where
failed attempts fail.**

1. **What is the state?** What does `dp[i]` *mean*, in one sentence?
2. **What is the recurrence?** How does `dp[i]` follow from earlier entries?
3. **What are the base cases?**

If you cannot say (1) in a sentence, do not write code yet. Most broken DP is
not a coding error, it is a state that does not carry enough information —
and no amount of debugging fixes that.

Say the sentence out loud in the interview. "`dp[i]` is the most I can steal
from the first i houses." That single sentence tells the interviewer you have
solved it, before you write anything.

## The take-or-skip shape

<Snippet file="code/dp_1d.py" symbol="rob" title="House Robber" />

The most common 1-D DP there is: at each element, either take it (and add
whatever was best two steps back) or skip it (and keep what was best one step
back).

Note there is no array. Only `dp[i-1]` and `dp[i-2]` are ever read, so the
table folds to two variables and the space is O(1). **Do this fold in the
round** — write the array version first if it helps you think, then say "only
the last two entries are read, so I can drop the array", and do it. It is a
free demonstration of understanding.

## Counting versus optimising

<Snippet file="code/dp_1d.py" symbol="coin_change" title="Coin Change — minimising" />

`dp[a]` is the fewest coins for amount a, so the recurrence takes a `min`. If
the question were "how many ways", the recurrence would `sum` instead — and
the loop order would matter, which is the subject of
[Grid & Knapsack DP](../dp-grid-knapsack/).

The sentinel `amount + 1` stands in for infinity: it is larger than any real
answer, so `min` never picks it, and the final check maps it to −1.

The inner loop runs **forward** over amounts, which permits reusing a coin.
That direction is the unbounded-knapsack signature.

## When a DP has a better form

<Snippet file="code/dp_1d.py" symbol="length_of_lis" title="LIS in O(n log n)" />

The natural DP is `dp[i]` = the longest increasing subsequence *ending at i*,
filled by scanning all earlier elements. O(n²), and it is a perfectly good
first answer.

The O(n log n) version keeps `tails[k]` = the smallest possible tail of an
increasing subsequence of length k + 1. Because `tails` is sorted, binary
search places each value, replacing the first tail that is not smaller.

**`tails` is not a valid subsequence.** Only its *length* is meaningful — the
values in it may never have appeared together in that order. Interviewers ask
this precisely to see whether you understand the algorithm or recall it; do
not claim otherwise. Reconstructing the actual subsequence needs a parent
array alongside.

<Snippet file="code/dp_1d.py" symbol="word_break" title="Word Break" />

Included because LeetCode tags it `trie`, which sends people down the wrong
path. It is 1-D DP: `dp[i]` means "the first i characters can be segmented",
and each position looks back for a reachable split leaving a valid word.

## Pitfalls

- **Writing code before naming the state.**
- **Off-by-one between `dp` indices and array indices.** `dp` usually has n + 1
  entries with `dp[0]` as the base. Be explicit about which is which.
- **Base cases.** `dp[0] = 1` for counting (one way to make nothing) versus
  `dp[0] = 0` for optimising. Getting these swapped produces answers that are
  wrong by a constant and look almost right.
- **Recursion depth** in the memoised top-down version. `@cache` plus n = 10⁵
  hits Python's limit; convert to bottom-up.
- **Reaching for DP when greedy works** (Jump Game) or greedy when DP is
  needed (Coin Change with arbitrary denominations). The test is whether you
  can construct an [exchange argument](../greedy/).

## Anchor walkthroughs

### House Robber

**Clarify.** Are values non-negative? (If negatives were allowed, "skip
everything" becomes an option and the base cases change.) Is the row circular?
(That is House Robber II.) Can the array be empty?

**State first.** "`dp[i]` = the most I can steal from the first i houses." Say
it before anything else.

**The recurrence.** `dp[i] = max(dp[i-1], dp[i-2] + nums[i])` — skip this
house, or rob it and take the best from two back.

**The fold.** Write the array, then collapse it to two variables and say why.

**Dry-run** `[2,1,1,2]` → 4 (first and last). The greedy "always take the
larger neighbour" gets 3 here, so this input also demonstrates why greedy
fails — worth pointing at.

**Follow-up:** House Robber II, houses in a circle. The trick is that the
first and last are now adjacent, so run the linear version twice — once
excluding the first house, once excluding the last — and take the max. That
reduction is the whole solution.

### Coin Change

**Clarify.** Is the coin supply unlimited? Can the amount be 0? (Answer 0.) Is
it fewest coins or number of ways? (Different problems; ask.) Are denominations
arbitrary?

**Why greedy fails**, with the counterexample ready: coins `[1, 3, 4]`, amount
6. Greedy takes 4, then 1, then 1 — three coins. Optimal is 3 + 3 — two coins.
Producing this immediately is the strongest thing you can do on this question,
because it proves you are not guessing.

**State.** "`dp[a]` = fewest coins summing to exactly a."

**Complexity.** O(amount × coins). Note this is *pseudo-polynomial* — linear
in the amount's magnitude, not in its number of digits. That precision is
appreciated.

**Dry-run** `coins=[1,2,5], amount=11` → 3 (5+5+1). Check `dp[3] = 2` on the
way (2+1).

**Follow-up:** Coin Change II, the number of combinations, where the loop
order decides whether you count combinations or permutations — see
[Grid & Knapsack DP](../dp-grid-knapsack/).

### Longest Increasing Subsequence

**Clarify.** Strictly increasing, or non-decreasing? (Strict on LeetCode —
and it is `bisect_left` versus `bisect_right`, a one-word change.) Subsequence,
not substring? (Yes — not contiguous.) Return the length or the sequence?

**Give the O(n²) DP first.** It is the honest starting point and it is easy to
state: `dp[i]` = LIS ending at i.

**Then the O(n log n) version**, with the caveat about `tails` above.

**Dry-run** `[10,9,2,5,3,7,101,18]`. `tails` evolves `[10] → [9] → [2] → [2,5]
→ [2,3] → [2,3,7] → [2,3,7,101] → [2,3,7,18]`. Length 4. Point out that
`[2,3,7,18]` happens to be a real subsequence here but need not be in general.

**Follow-up:** Russian Doll Envelopes — sort by width ascending and height
*descending*, then LIS on heights. The descending tie-break is what stops two
envelopes of equal width both being counted, and spotting it is the entire
difficulty of that problem.

## The idea

These are rare, and worth exactly the effort of **recognising them plus one
template each**. Recognition carries most of the value: knowing that "critical
connection" means *bridge* gets you most of the way, because the algorithm is
short once you know its name and hopeless if you try to invent it.

## Bipartite checking

<Snippet file="code/advanced_graphs.py" symbol="is_bipartite" title="Two-colour with BFS" />

Colour a node, colour its neighbours the opposite, and fail on a conflict. It
is equivalent to "the graph has no odd-length cycle", which is the phrasing
that makes Possible Bipartition recognisable as the same problem in disguise.

Every component needs its own start — the graph may be disconnected, and a
loop over all nodes is the fix.

## Bridges

<Snippet file="code/advanced_graphs.py" symbol="critical_connections" title="Tarjan's bridge-finding" />

Two timestamps per node:

- **`disc[u]`** — when u was first discovered.
- **`low[u]`** — the earliest discovery time reachable from u's subtree using
  at most one back edge.

An edge (u, v) is a bridge exactly when **`low[v] > disc[u]`**: v's entire
subtree has no other route back to u or above it, so that edge is the only
link and removing it disconnects them.

The `if neighbour == parent: continue` matters — the edge you arrived on is
not a back edge, and treating it as one makes every edge look non-critical.
(With parallel edges you must skip by edge id rather than by parent node;
worth a sentence if the input allows them.)

## Eulerian paths

<Snippet file="code/advanced_graphs.py" symbol="find_eulerian_path" title="Hierholzer's algorithm" />

Use every edge exactly once. Hierholzer's, and the counter-intuitive part is
that **the answer is built backwards**: a node is appended to the route only
once it has no unused edges left, and the finished list is reversed.

Why the obvious greedy fails: a plain DFS that always takes the smallest next
airport can walk into a dead end with edges still unused, and it has no way to
back out. Hierholzer handles that naturally — the dead end is appended first
and ends up at the *end* of the reversed route, exactly where it belongs.

**The existence conditions** are worth knowing even though LeetCode guarantees
a solution: a directed graph has an Eulerian path iff it is connected and at
most one node has `out − in = 1` (the start), at most one has `in − out = 1`
(the end), and everything else is balanced.

## Elimination

<Snippet file="code/advanced_graphs.py" symbol="find_celebrity" title="Find the Celebrity" />

Not a classical graph algorithm, but the same reasoning and a Meta favourite.

The naive solution asks all n² pairs. The insight is that **each question
eliminates somebody**: if the candidate knows i, the candidate is not the
celebrity; if not, i is not. So n − 1 questions leave exactly one candidate,
who then needs verifying in another 2n questions. O(n) total against O(n²).

Recognising "each comparison eliminates one" as a technique is transferable —
it is the same idea behind Boyer-Moore majority vote.

## Pitfalls

- **Recursion depth** in Tarjan. V = 10⁵ overflows Python's stack; say so and
  offer the iterative version.
- **Disconnected graphs.** Loop over every node.
- **Parallel edges** breaking the parent check.
- **Trying to derive these in the round.** If you do not recognise the
  algorithm, say what you *do* know — "this is asking for edges whose removal
  disconnects the graph, which are bridges; I know Tarjan's finds them in
  linear time but I'd need to reconstruct the low-link details" — which is a
  far better outcome than silence or a broken attempt.

## Anchor walkthroughs

### Reconstruct Itinerary

**Clarify.** Must every ticket be used exactly once? (Yes — that is what makes
it Eulerian rather than a path search.) Is the answer unique? (Ties broken
lexicographically.) Is a valid itinerary guaranteed?

**The trap, and the reason to run the second test case.** The greedy "always
fly to the smallest next airport" fails on
`[["JFK","SFO"],["JFK","ATL"],["SFO","ATL"],["ATL","JFK"],["ATL","SFO"]]`.
Greedy goes JFK→ATL→JFK→SFO→ATL→SFO — which happens to be right — but a naive
implementation that cannot backtrack strands itself. Work that example
explicitly; it is why the problem is Hard.

**The insight.** Hierholzer's: descend greedily until stuck, then append the
stuck node and unwind. Reverse at the end.

**The lexicographic requirement** is handled by keeping each node's
destinations reverse-sorted so `pop()` yields the smallest — a small detail
that saves a heap.

**Complexity.** O(E log E) for the sort, O(E) for the walk.

### Critical Connections in a Network

**Clarify.** Undirected? Connected to begin with? May there be duplicate
edges?

**The naive answer.** Remove each edge and test connectivity: O(E · (V + E)).
Say it — it is correct, and at E = 10⁵ it is far too slow, which motivates
Tarjan.

**The insight.** One DFS. Track discovery times and low-links; an edge is a
bridge when the subtree below it cannot reach back above.

**Dry-run** a triangle `0-1-2-0` with a pendant `1-3`. Inside the triangle,
every node can reach back via the cycle, so `low <= disc` everywhere and there
are no bridges. Node 3 has only the one edge, so `low[3] = disc[3] > disc[1]`
and `1-3` is a bridge. That contrast — cycle versus pendant — is the clearest
way to explain the condition.

**Complexity.** O(V + E).

### Is Graph Bipartite?

**Clarify.** Is the graph connected? (Not necessarily.) Are self-loops
possible? (A self-loop makes it non-bipartite immediately.) Is the adjacency
list symmetric?

**The insight.** Two-colouring. A conflict means an odd cycle.

**BFS or DFS?** Both work. BFS is slightly easier to reason about because
colour alternates with level, and it avoids the recursion-depth question.

**Dry-run** a 4-cycle (bipartite: colours alternate cleanly) then a triangle
(not: the third node conflicts with both neighbours). The two smallest cases
demonstrate the whole algorithm.

**Follow-up:** Possible Bipartition, which is the identical problem stated as
"split people into two groups given a list of who dislikes whom". Recognising
that restatement instantly is the point.
